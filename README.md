# 小说临时搜索

用于原站搜索升级期间的轻量过渡工具，供少量手机用户使用。

## 正式使用方式

正式网页由GitHubPages提供。页面只读取仓库中的静态索引，在浏览器本地执行单关键词包含搜索，不会在搜索时请求原站。

- 搜索对象是网站返回的完整文件名，关键词只去除首尾空格。
- 英文匹配不区分大小写，中文匹配保持包含关系。
- 分类为全部、言情、耽美、男生。
- 页面显示数据最后更新时间，结果保留原站详情链接。
- 有真实直链的结果显示直接下载，没有直链的结果仍显示详情。
- 查看疑似错区和只看可直接下载均为人工抽查入口，可与分类筛选共存；普通搜索仍要求关键词。

为适配手机浏览器，言情和耽美索引按每片4000条拆分，男生索引为单片。浏览器逐片下载和匹配，使用IndexedDB持久缓存原始JSON、版本和分片指纹：首次使用下载所需分片，同版本再次打开只检查manifest，版本变化只同步变化分片，失败时保留旧版本并自动重试。当前分片单片约1.18MB以内。

## GitHubActions更新

`.github/workflows/update-pages.yml`当前已暂停自动定时触发，仅支持`workflow_dispatch`手动运行。此前的北京时间08:00、14:00、20:00（UTC 00:00、06:00、12:00）定时计划不再自动执行。

每次运行从三分类第一页开始增量抓取，以hash去重；遇到已有hash后停止继续翻页，设置最大分页保护，保留旧索引并及时写入新数据。只有索引实际变化才提交，完成后生成`public/data/manifest.json`、分类分片和更新时间文件并部署到GitHubPages。单个分类失败不会清空旧索引，Actions不执行历史全量初始化。

## 首次部署GitHubPages

1. 将本仓库推送到GitHub。
2. 在仓库Settings→Pages中将Source设为GitHubActions。
3. 在Actions页面手动运行一次更新工作流。
4. Pages部署完成后，使用GitHub提供的页面地址访问。

工作流使用`GITHUB_TOKEN`提交索引更新，不需要额外私密Token或密码。

## 本地开发与历史详情补全

要求Node.js20+。

```bash
npm test
npm start
```

本地Node服务仅用于调试和维护，正式Pages网页不依赖公网Node、Worker或用户电脑常驻。

基础历史索引初始化仅在本地手动执行，按页顺序抓取、低频请求、逐页落盘并支持中断续跑：

```bash
npm run init:all
npm run build:static-index
```

日常增量更新使用：

```bash
npm run update:index
```

详情页backfill用于逐步补齐标签票数、疑似错区辅助信息和真实下载直链，单请求顺序执行，成功一条立即落盘，按hash跳过已处理记录，失败记录后续重试：

```bash
npm run backfill:detail
npm run backfill:detail -- --download-only --limit=1000
```

普通详情backfill默认按每批1000条连续执行，本轮最多处理10000条新的未处理记录；可用`--max-total`调整上限。连续请求异常达到阈值时会安全停止，已落盘记录保留。

`downloadUrls`只保存HTTPS且路径匹配`/down.php/`的直链，并排除公告和阅读页。当前约1000条详情记录已处理，992条有真实直链，8条失败待后续重试；不代表已完成全量8万多条详情补全。下一步继续新的约1000条历史详情backfill，并观察疑似错区准确率、downloadUrls覆盖率和镜像可用性。

详情标签仅用于疑似错区抽查，不改变正式原始分类筛选。日期已补全年份，按完整日期倒序显示，格式为`YYYY-MM-DD HH:mm`，没有时分时仅显示`YYYY-MM-DD`。

## 已知限制

GitHubPages只提供静态网页，最新数据取决于最近一次手动触发GitHubActions并成功运行，不会在用户搜索时实时刷新。当前自动定时更新已暂停。原站页面结构、访问规则、下载镜像可用性或中文语言要求变化时，更新或直链可能失败，但已有静态索引仍可搜索。原始TXT编码和下载响应头不统一，部分手机可能出现正文或文件名乱码；项目不引入代理、转码或后端处理。
